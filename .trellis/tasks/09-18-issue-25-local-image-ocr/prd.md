# 实施 Issue 25 翻译页本地图片取字

## Goal

让用户在无法复制网页、图片或界面截图中的文字时，能够在翻译页直接粘贴或拖入一张图片，由本机 OCR 提取文字并沿用现有文本翻译链路自动翻译；图片不得上传给 LLM 或写入任何持久化存储。

- 远端标签：`enhancement`、`ready-for-agent`。

## Confirmed requirements

### 用户入口与结果

1. 翻译页原文输入区支持直接粘贴剪贴板位图，以及拖入单个 PNG、JPEG、WebP 图片文件。
2. 剪贴板同时含图片和文字时图片优先；没有有效图片时保留浏览器的普通文字粘贴行为。
3. 首期不增加文件选择按钮、OCR 引擎设置或 OCR 语言设置。
4. 识别成功且非空时，以 OCR 文本替换原文，并使用当时选定的源语言、目标语言、Provider 和模型自动发起一次现有文本翻译。
5. 识别中、拖入命中、失败和取消必须在原文区域提供可观察、可本地化、可访问的反馈。

### 稳定内容与并发

1. 图片识别期间保留上一次稳定的原文和译文；只有当前最新请求成功且结果非空时才替换原文。
2. 新图片、手动修改原文或新的文字粘贴均视为更新的用户输入，必须取消旧 OCR，并使旧结果无法覆盖新内容。
3. 新图片开始时必须取消仍在运行的旧翻译；不能只在前端隐藏迟到结果而让 LLM 请求继续消耗资源。
4. OCR 和翻译均使用请求标识与递增序号双重守卫：后端尽力中止底层工作，前端拒绝任何迟到回调。
5. 切换页面或隐藏主窗口不取消当前 OCR；任务状态脱离视图组件生命周期，完成后仍可继续自动翻译。

### 错误与限制

1. 一次只允许一张图片。多图必须明确拒绝且不启动 OCR，不能静默只取第一张。
2. 格式不支持、编码体积或解码尺寸超限、系统缺少识别语言、无文字、取消或识别失败时，保留上一次稳定内容且不调用 LLM。
3. 错误信息不得包含图片原始字节、绝对路径、API Key 或上游敏感响应。
4. 图片只在内存中经过前端、Tauri IPC 与本地 OCR 能力；不得写入文档 SQLite、IndexedDB 收藏、配置或日志。

### 平台交付

1. Windows 首发使用 `Windows.Media.Ocr.OcrEngine`，只使用系统已安装 OCR 语言；缺少语言时给出安装引导，不回退到网络服务。
2. macOS 使用 Apple Vision，Linux 随应用发行 Tesseract 5 与明确的语言数据；两者必须在目标平台完成运行、取消、离线、质量与打包验收后才可开放。
3. Windows 通过不能表述为三平台通过，也不能单独作为关闭 Issue 25 的证据。

## Acceptance criteria

- [ ] Windows、macOS、Linux 均按各自方案在目标平台完成真实离线 OCR 验收；未验收平台保持明确不可用。
- [ ] 三平台共享同一内存输入、UTF-8 文本输出、可取消和错误分类合约；调用侧不存在平台判断。
- [ ] 粘贴、拖放、图片优先、多图拒绝、成功替换、自动翻译、失败保留和连续请求均有自动化覆盖。
- [ ] OCR 为空、失败或取消时，真实 LLM 请求计数保持为零；被新图片替代的旧翻译可在后端观察到取消。
- [ ] 图片字节未进入 LLM 消息、文档库、收藏、配置、日志或错误文本。
- [ ] Linux 安装包包含约定的中英文语言数据，且 Tesseract、Leptonica、Rust 包装层和训练数据均进入生成的第三方声明。
- [ ] 最终交付报告分别列出本地自动化、Windows 系统验收、macOS 目标机验收、Linux 目标机验收和远端 GitHub 状态。
- [ ] GitHub Issue 只在默认分支包含全部交付、必要验收完成且用户另行授权后关闭。

## Out of scope

- PDF、DOCX 或其他文档 OCR。
- 将图片发送给视觉模型或任何网络 OCR 服务。
- 多图批处理、图片历史、图片收藏、图片持久化或独立 OCR 校对器。
- 自动下载系统语言包或运行时下载 Linux 语言数据。
- 要求三平台识别质量逐字一致。
