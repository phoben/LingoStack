# V1 智能翻译契约与可靠性

## Goal

让用户的一次翻译请求同时得到可流式阅读的译文和最多 5 个上下文相关的专业 IT 词条解释，并让语言规则、异常重试与变量命名输出达到稳定可测的 V1 行为。

## Requirements

- 单次 translate 模型调用返回译文与 0–5 个词条；不得额外发 Explain 请求。
- 词条仅限 `technology`、`programming`、`product`，必须出现在原文或译文中，去重后最多 5 项；解释用检测/选择出的原文语种。
- 译文在词条元数据完成前持续流式显示；sentinel/JSON 永不泄漏到正文。
- 元数据缺失或损坏时保留译文、隐藏无效 tag，并允许用户重试。
- 自定义翻译 Prompt 只能覆盖风格，固定机器协议始终追加且不可覆盖。
- 自动源语言与默认目标语言真实使用 core 规则；用户当前请求的显式选择优先。
- 网络/超时/5xx/429 在零输出时最多自动重试一次；有部分输出后不自动重放。
- 命名结果固定为 5 个中性候选 × 5 种命名形式，过多截断、过少/畸形给出明确结果状态。

## Acceptance Criteria

- [ ] 以示例原文 “Copilot memory and Ollama in GitHub Copilot for JetBrains” 翻译时，mock 响应可产生流式译文和不超过 5 个专业 tag；普通词 `memory` 不作为 tag。
- [ ] 每个 tag 可由 hover 和键盘 focus 查看原文语种解释；0 个词条时不渲染空容器。
- [ ] sentinel/JSON 被任意 chunk 切分、JSON 非法或流在元数据阶段失败时，正文无协议泄漏且已生成译文保留。
- [ ] 语言映射、界面语言、同语种转英文和全局目标四级规则在真实翻译入口生效。
- [ ] 429/超时/网络/5xx 的零输出路径最多调用两次；401/403、协议错误和部分输出错误只调用一次。
- [ ] 内置/自定义 Prompt 都保留强制词条协议；试图要求其他格式的自定义 Prompt 不能覆盖协议。
- [ ] 命名界面稳定展示恰好 5 行 × 5 列，少于 5 条时明确提示未完整生成，超过 5 条时只取前 5 条。
- [ ] Rust、Vitest、RTL 与 provider mock 测试覆盖上述边界，全量门禁通过。

## Out of Scope

- 独立解释页、解释模式或第二次解释请求。
- 独立浮窗/工具栏、文档翻译、模型专属 function calling/JSON mode。
- 本地通用 IT 术语词典或额外分类模型。
