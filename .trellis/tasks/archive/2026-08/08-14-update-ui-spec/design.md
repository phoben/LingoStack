# Design · 当前项目 UI 规范更新

## 1. 文档边界

新增 `.trellis/spec/lingostack-app/frontend/ui-design.md`，作为“当前界面应呈现什么”的主契约；
现有 `components-and-styling.md` 继续负责“React/Tailwind 组件如何实现”；
`testing-and-a11y.md` 负责可访问性和验证。`index.md` 负责按任务路由。

这样能把视觉/体验契约与组件工程写法分开，同时避免把所有内容继续堆进已有 105 行的组件文档。

## 2. 证据与冲突解析

规范明确采用以下顺序：

```text
当前生产源码
  > 已落地的 Trellis 规范与产品决策
  > 原始 lingostack-design 设计包
```

原始设计包仍提供品牌气质、颜色语义和排版意图；当它与当前实现冲突时，规范列出差异并以当前
实现为准，避免未来开发“照原型”恢复已取消的状态栏、流式光标或嵌套卡片。

## 3. `ui-design.md` 内容结构

1. 适用范围与证据优先级
2. 体验目标：安静、紧凑、精密、内容优先
3. 桌面窗口与应用骨架
4. 视觉令牌：主题、颜色、字体、密度、圆角、阴影、图标、动效
5. 布局层级：单层主面板、工具条、分栏、行表、分节、合法例外
6. 组件与内容语义：主操作、次级操作、mono、标签、状态文本
7. 交互状态矩阵：default / hover / focus / active / disabled / loading / empty / error / success
8. 桌面窗口适配与 overflow 契约
9. Good / Base / Bad 场景和 Wrong vs Correct 示例
10. UI 变更所需检查与验收点

文档只写已在当前实现中形成的契约；不一致之处列为缺口，不把目标设计伪装成现状。

## 4. 现有文档调整

### `components-and-styling.md`

- 在开头链接 `ui-design.md` 并说明视觉契约优先级。
- 保留手写原语、变体表、`cn()`、原生 `Select`、视图路由、主题接线等工程约定。
- 将视觉层级、令牌与状态说明收敛为实现映射，避免与新文档重复。
- 补充组合组件示例和“何时抽原语、何时保留页面局部组件”的边界。

### `testing-and-a11y.md`

- 把“全站没有 live region”更新为当前三处已覆盖及剩余缺口。
- 用状态区域契约说明 `aria-live`、`aria-busy`、`role="alert"` 的适用关系。
- 保留已确认的语义属性、键盘操作与测试查询约定。

### `index.md`

- 增加 UI 设计规范入口。
- 把不可执行的“必须调用 `/lingostack-design`”改成可执行的证据读取顺序；当该技能在宿主可用时
  可以调用，不可用时直接读取仓库内设计资料与当前源码。
- 修正已过时的 `aria-live` 缺口描述。

## 5. 兼容性与风险

- 不改产品代码、依赖或运行时行为。
- 最大风险是文档将旧原型当作当前产品，或多个规范文件对同一规则给出不同答案。
- 通过单一主契约、交叉链接和全文冲突搜索降低风险。
- 不承诺当前未实现的响应式行为、字体加载、测试覆盖或可访问性能力。

## 6. 回滚

文档改动按文件独立可回滚。新增 `ui-design.md` 若结构不合适，可删除并恢复索引；不会影响构建
产物或用户数据。
