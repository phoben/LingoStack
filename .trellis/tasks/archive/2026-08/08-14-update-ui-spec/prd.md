# 更新当前项目 UI 规范

## Goal

以当前已实现的 LingoStack 主窗口 UI 为基准，更新前端 UI code-spec，使后续开发者与 AI
能够复用现有视觉语言、布局结构和交互反馈，不再把已经过时的原型规则重新引入产品。

用户价值：新增或调整界面时能保持“安静、紧凑、精密”的桌面开发者工具体验，避免页面
重新出现嵌套卡片、割裂的操作区、错误的颜色语义或不一致的状态反馈。

## Confirmed Facts

- 当前生产界面的视觉真源是 `src/` 中的实际实现；仓库内
  `.claude/skills/lingostack-design/` 用于解释设计意图，但其中部分原型约定已经被后续
  产品决策覆盖。
- 当前应用骨架是 44px 自定义标题栏、可拖拽调宽的左侧导航，以及右侧唯一一层圆角主面板：
  `src/App.tsx:55-65`、`src/components/title-bar.tsx:70-128`、
  `src/components/sidebar.tsx:21-126`。
- 当前视图区不使用嵌套圆角卡片；工具条、左右栏、网格列和行表通过 1px 语义分割线
  分区：`src/components/view-shell.tsx:12-31`、
  `.trellis/spec/lingostack-app/frontend/components-and-styling.md`。
- 颜色、字体、圆角、阴影和动效均由 `src/index.css` 与 `tailwind.config.ts` 的语义令牌
  提供；组件不得散落硬编码主题色。
- `src/components/ui/` 是当前项目的手写原语层，不是 shadcn 生成物；原语使用原生属性、
  `forwardRef`、`cn()` 和手写变体表。
- 当前代码已经实现浅色、深色、跟随系统三种主题，并通过 React 挂载前脚本避免主题闪烁。
- 当前异步结果区已出现 `aria-live`、`aria-busy` 与错误 `role="alert"` 的实际用法；
  规范中的旧“全站没有 aria-live”描述已经过时，需要按当前代码校正。
- 旧设计包中的固定 188px 侧栏、嵌套卡片、底部状态栏、流式闪烁光标与当前产品不一致，
  不能作为新的实现要求。

## Requirements

- 用户确认范围覆盖视觉样式、布局组件、交互状态、可访问性与桌面窗口适配。
- R1：明确 UI 规范的证据优先级：当前生产源码 > 已落地的 Trellis 决策 > 原始设计包；
  原型仅补充当前代码尚未覆盖的场景。
- R2：更新现有前端规范，准确记录当前应用骨架、单层主面板和分割线分区规则，并给出
  可复制的正确/错误示例。
- R3：记录当前语义令牌、排版、间距、圆角、阴影、图标与动效使用边界，禁止新增散落的
  主题硬编码和第二套组件风格。
- R4：记录当前 UI 原语与复用边界，包括按钮、输入、选择器、文本域、状态标签、图标按钮、
  行表、分节和视图工具条。
- R5：记录各类可观察状态的呈现契约：默认、悬停、聚焦、选中、禁用、加载、空态、错误、
  成功与异步播报。
- R6：同步前端规范索引，删除或修正与当前实现冲突、已失效或无法执行的说明。
- R7：规范更新仅描述已确认的当前规则；源码未形成统一做法的内容必须标为例外、缺口或
  待决策项，不得伪装成既有规范。

## Acceptance Criteria

- [ ] AC1：规范明确说明当前主窗口层级，以及“主面板内用分割线、不得恢复嵌套卡片”的
      适用场景和合法例外，并至少给出一组 Wrong vs Correct。
- [ ] AC2：规范列出当前主题与语义色角色、字体语义、常用字号/密度、圆角、阴影、动效，
      每项均能追溯到当前 `src/index.css`、`tailwind.config.ts` 或组件源码。
- [ ] AC3：规范覆盖已有 UI 原语和页面组合模式，包含具体组件签名或 Tailwind 示例，足以
      指导新增界面保持一致。
- [ ] AC4：规范覆盖 default / hover / focus / active / disabled / loading / empty / error /
      success 的表现与可访问性要求，并纠正已过时的 `aria-live` 覆盖描述。
- [ ] AC5：前端规范索引能把后续 UI 工作路由到正确文档，不再依赖当前环境未暴露的命令
      作为唯一前置步骤。
- [ ] AC6：文档内所有路径、组件名、令牌名和示例经静态核对存在；无旧原型与当前代码冲突。
- [ ] AC7：执行 Markdown/格式检查（若仓库有对应命令）以及 `git diff --check`；文档任务不把
      未执行的 UI 运行验证表述为已验证。

## Out of Scope

- 不修改 React、CSS、Tailwind 配置或任何业务代码来“配合规范”。
- 不重新设计页面，不恢复旧原型中的状态栏、流式光标或嵌套卡片。
- 不在本任务补齐现存 UI 测试或可访问性缺口；只准确记录当前契约和已知缺口。
- 不迁移到 shadcn/Radix/CVA，也不新增依赖。

## Technical Notes

- 这是一项纯 code-spec 更新，不触发 API、IPC、数据库或基础设施契约变更。
- 规范应把“当前已实现规则”与“仍存在的缺口”分开；不得把旧原型的响应式网站矩阵当成
  当前 Tauri 桌面窗口的已实现能力。
