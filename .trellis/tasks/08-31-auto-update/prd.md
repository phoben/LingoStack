# LingoStack 自动更新

## Goal

为 Windows x64 安装版提供可靠、低打扰、可审计的自动更新：兼顾中国大陆网络可达性，自动发现稳定版更新，由用户显式触发下载，随后完成签名校验、安装和重启，同时不引入遥测或自研更新协议。

## Background

- LingoStack 是基于 Tauri 2 的跨平台开源桌面应用；当前只有 Windows x64 NSIS 发布产物与真实桌面验收基础。
- 当前应用版本由 `package.json`、workspace `Cargo.toml` 与 `src-tauri/tauri.conf.json` 三处共同维护；本地发布脚本不签名、不上传，也不生成更新索引。
- 当前未接入 updater/process 插件、更新 ACL 或远程发布 workflow；About 页已有“检查更新”占位，应用已有全局轻量 Toast、标题栏与托盘机制。
- `lsupdates.yugasoft.cn` 已部署为公开更新域名；2026-09-01 已验证 CNAME、HTTPS、TLS 1.2、私有 COS 回源和三类路径重写，stable manifest 尚待首次正式发布。

## Requirements

### R1. 检查策略

- 应用界面初始化后静默检查一次；进程常驻托盘期间每 24 小时再静默检查一次。
- About 页始终提供手动检查；手动检查与自动检查、下载之间不得并发。
- 发现可用更新后停止周期检查，直到更新完成或下次启动。
- 不提供关闭自动检查的设置项。启动自动检查失败保持静默且不得误报“已是最新版”；手动检查必须明确反馈“已是最新版 / 有可用更新 / 检查失败”。
- 应用内只跟随稳定版，且只接受版本号高于当前版本的更新。

### R2. 发现更新后的体验

- 发现更新后复用全局非阻塞 Toast，不抢焦点、不弹模态窗口。
- About 页的“检查更新”按钮持续变为“立即更新”；标题栏在主题按钮与系统窗控之间显示更新图标。没有可用更新时隐藏标题栏图标。
- Toast 与标题栏只显示目标版本；About 页展示目标版本、发布日期、纯文本更新摘要及 `https://github.com/phoben/LingoStack/releases/tag/v<version>` 完整变更链接。
- 两个“立即更新”入口行为一致、键盘可达，并不得影响标题栏拖拽或窗口控制。

### R3. 下载、安装与重启

- 自动检查只检查，不下载。只有用户点击“立即更新”后才开始下载。
- 点击后不切换当前视图、不弹进度窗口；标题栏图标显示下载活动状态，About 页显示 0–100% 进度，主功能保持可用。
- 用户点击即授权本次下载、安装与重启；下载完成后无需再次确认，当前应用退出并由 Tauri 官方 NSIS passive 安装器完成安装、显示短进度并自动启动新版本。
- 首期不提供取消、暂停或断点续传控制；安装开始前用户可通过显式退出应用中止本次下载。
- 所有更新均可延期，不得因未更新而阻止用户使用主功能。

### R4. 分发与发布

- 使用 Tauri 官方 Updater 与签名机制，不自研更新协议、验签或安装器。
- 腾讯云 COS 私有源桶是发布存储，已备案中国内地 CDN 域名 `lsupdates.yugasoft.cn` 是应用内唯一权威更新源；CDN 使用回源鉴权，对外 URL 不使用会过期的查询签名。
- 稳定索引固定为 `https://lsupdates.yugasoft.cn/channels/stable/latest.json`。版本产物使用不可变路径，稳定索引使用短缓存并在发布后刷新 CDN。
- GitHub Releases 保留公开发布记录与手动下载镜像，但不作为应用内自动更新 endpoint；预发布版本不得进入稳定索引。
- 正式版由 SemVer Git 标签触发 GitHub Actions，经 `production` 环境人工批准后构建、签名、发布 GitHub Release、上传并验证 COS 产物，最后切换稳定索引。
- 客户端协议保持厂商无关；COS CLI/SDK 与凭据只存在于发布流水线边界。

### R5. 安全、隐私与恢复

- 更新包安装前必须通过 Tauri 签名验证；验签失败不得安装或破坏当前版本。
- 更新请求只允许包含协议所需的当前版本、平台、架构与标准网络头，不携带用户标识、API Key、翻译内容或其他业务数据。
- 签名私钥和密码不得进入仓库、`.env`、日志或构建产物。GitHub `production` 环境保存发布副本，维护者另行保存独立离线加密备份；首次公开发布前记录公钥指纹并完成恢复演练。
- 计划轮换签名密钥时，先发布由旧私钥签名、但内置新公钥的桥接版本；旧私钥丢失或泄露时不得伪装为可自动恢复。
- 首期不支持自动降级。误发时先恢复上一健康稳定索引以阻止继续扩散，再发布更高版本号的修复包；无法启动的已更新客户端通过官网手动重装。
- 自动更新错误只记录脱敏信息，不记录云凭据、用户内容或完整敏感响应体。

## Acceptance Criteria

- [ ] AC1. Windows x64 NSIS 安装版在启动后及连续运行满 24 小时时各执行一次静默检查，不在 24 小时窗口内重复自动请求。
- [ ] AC2. 同一网络故障在自动检查时不打扰用户，在手动检查时产生可理解且可重试的反馈；无更新时明确显示“已是最新版”。
- [ ] AC3. 发现正式稳定版后只提示、不下载；Toast 消失后，About 页“立即更新”和标题栏图标仍提供持续入口，且同一版本不重复提示。
- [ ] AC4. About 页展示受信任的版本、日期、纯文本摘要与 GitHub HTTPS 链接；远端内容不执行 HTML。
- [ ] AC5. 任一入口启动唯一更新任务；下载期间当前视图可继续使用，标题栏显示活动状态，About 页显示进度；完成后当前应用退出，NSIS passive 安装器完成安装并自动启动新版本。
- [ ] AC6. 用户忽略更新时主功能保持可用；客户端不接受低于或等于当前版本的自动更新。
- [ ] AC7. 无效签名、损坏产物、网络中断或安装失败均不会破坏当前版本，并恢复可重试入口；自动与手动错误提示遵守 R1。
- [ ] AC8. 未经 `production` 批准的 workflow 无法读取生产签名密钥或写入 COS；任一步失败都不会更新稳定索引。
- [ ] AC9. 发布任务先验证不可变产物、签名与 GitHub Release，再最后发布稳定索引；索引、TLS、缓存头和所有 URL 通过公开网络验收。
- [ ] AC10. 客户端、日志、测试和发布产物均不包含 API Key、COS 凭据或 Tauri 签名私钥；密钥恢复演练有不含秘密的记录。
- [ ] AC11. 误发 runbook 能恢复上一健康索引并指导发布更高修复版本；不承诺自动降级。
- [ ] AC12. macOS/Linux 与 portable 构建不暴露未经验证的自动更新承诺；后续接入必须补齐对应签名、安装包和目标平台验收。

## Out of Scope

- macOS/Linux 自动更新、Windows portable 自动更新，以及 MSI 更新渠道。
- 强制更新、最低版本阻断、自动降级与远端强制回退。
- Beta/Nightly 应用内通道、频道切换设置和关闭自动检查的设置。
- 下载取消、暂停、断点续传和阻塞式更新进度窗口。
- 自研更新协议、签名算法、安装器或托管更新 SaaS。
- 本任务中直接修改腾讯云、DNS、CDN 或 GitHub 仓库外部配置；这些按发布 runbook 由授权维护者完成。

## Deployment Prerequisites

以下事项不改变产品设计，但会阻断真实远程发布验收：

- 配置 `lsupdates.yugasoft.cn` 的 DNS/CNAME、TLS、COS 私有回源与 CDN 缓存/刷新规则。
- 提供受限 CAM 发布身份、COS Bucket/Region/Prefix 与 CDN 刷新权限，写入 GitHub `production` environment secrets/variables。
- 生成 Tauri 更新签名密钥，配置 GitHub 发布副本和独立离线备份，并完成一次恢复演练。

当前没有未解决的产品、范围、UX、兼容性或风险决策。
