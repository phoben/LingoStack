# 设计自动更新能力

## Goal

为 LingoStack 提供可靠、低打扰的桌面自动更新能力：兼顾中国大陆网络可达性，在应用启动与用户主动操作时发现新版本，在后台完成下载，并由用户明确触发安装与重启。

## Background

- LingoStack 是面向程序员的跨平台开源桌面应用，基于 Tauri 2。
- 用户希望遵循开源桌面软件的通行体验，同时优先保障中国大陆网络环境下的更新可用性。
- 应优先采用成熟的第三方库或官方方案，避免自研更新协议、签名校验或安装器流程。
- 当前处于需求与设计访谈阶段；任务创建许可不代表实现许可。

## Confirmed Facts

- 当前应用版本为 `0.0.2`，版本号由 `package.json`、workspace `Cargo.toml` 与 `src-tauri/tauri.conf.json` 三处共同维护。
- 当前发布脚本仅支持 Windows 免安装程序与 NSIS 安装程序的本地构建，不负责签名、更新索引、上传或远程发布。
- 当前项目未接入 updater、process 或 notification 插件；生产 ACL 也未开放更新能力。
- About 页面已有“检查更新”禁用占位按钮；应用顶层已有全局 toast、主窗口/托盘恢复机制，可作为更新体验的复用边界。
- Tauri 2 官方 Updater 支持签名更新包、静态 JSON 更新索引、后台下载进度、安装与重启流程；静态索引与产物可托管在 HTTPS 对象存储/CDN。
- 首期无需自研更新协议，也无需为基本更新能力依赖第三方更新 SaaS；动态灰度或复杂频道策略出现后再评估托管服务。
- 当前只有 Windows x64 NSIS 发布产物及真实桌面验收基础；macOS/Linux 尚不具备签名、公证和目标平台验收链路。

## Requirements

- 支持应用启动后自动检查更新。
- 支持用户在界面中手动检查更新。
- 自动检查发现新版本后弹出提示，并将既有检查入口切换为“立即更新”。
- 新版本提示复用全局轻量、非阻塞 Toast；提示不抢焦点，也不要求用户立即处理。
- 有可用更新时，About 页的“检查更新”按钮持续变为“立即更新”；标题栏在主题按钮与系统窗控之间动态显示一个更新图标。两个入口均直接触发同一“立即更新”流程。
- 没有可用更新时不显示标题栏更新图标，About 页保留手动“检查更新”入口。
- 自动检查不得自动下载安装包；只有用户点击“立即更新”才开始下载。
- 用户点击“立即更新”即授权本次下载、安装与重启；下载期间不阻断翻译等主要功能，安装就绪后完成更新并重启应用。
- 首期所有更新均可延期；不设置会阻止用户进入或继续使用主功能的强制更新，也不从远端下发最低受支持版本策略。
- 更新分发应优先考虑中国大陆网络情况，可采用对象存储等稳定下载源。
- 国内 HTTPS 对象存储/CDN 是应用内唯一权威更新源，承载静态更新索引和签名产物。
- GitHub Releases 保留公开发布记录与手动下载镜像，但不作为应用内自动更新 endpoint；国内源故障时提示用户稍后重试或前往 GitHub 手动下载。
- 应用内首期只跟随稳定版通道；预发布版本可在 GitHub Releases 供手动测试，但不得写入权威更新索引，也不在设置中提供 Beta/Nightly 通道。
- 更新链路必须使用成熟第三方或 Tauri 官方能力完成签名验证与安装，避免重复造轮子。
- 首期只向 Windows x64 安装版交付自动更新；架构保留跨平台扩展能力，但不得在未经目标平台验证时宣称 macOS/Linux 可用。
- 保持开源项目可审计性，不上传 API Key、用户内容或遥测数据。

## Scope Decisions Needed

- 正式版发布触发方式、审批与回滚策略。
- 国内对象存储服务及其凭据接入方式。

## Acceptance Criteria

- [ ] Windows x64 安装版启动后可按已确认策略自动发现比当前版本更新的正式版本。
- [ ] 用户可在界面中主动检查，并明确看到“已是最新版 / 有可用更新 / 检查失败”之一。
- [ ] 自动检查发现新版本后只提醒，不在用户授权前下载更新包；检查入口变为“立即更新”。
- [ ] 新版本提示使用现有非阻塞 Toast；提示消失后，About 页“立即更新”和标题栏更新图标仍提供持续入口。
- [ ] 标题栏图标只在有可用更新时显示，具备本地化可访问名称和键盘操作能力，且不影响窗口拖拽、主题切换及最小化/最大化/关闭。
- [ ] 从 About 页按钮或标题栏图标触发的更新行为完全一致，不会启动两个并发下载。
- [ ] 用户点击“立即更新”后，更新包在后台下载，主功能保持可用，并呈现可理解的下载进度或状态。
- [ ] 下载完成后无需再次确认，应用执行安装并重启到新版本。
- [ ] 更新元数据与安装包经过成熟方案提供的完整性及签名验证；验证失败时不得安装。
- [ ] 应用只从国内权威更新源检查并下载；该源不可用时不误报最新版，并提供稍后重试与 GitHub 手动下载入口。
- [ ] 预发布版本不会被稳定版客户端发现；只有明确发布到稳定索引的正式版本才成为可用更新。
- [ ] 更新检查和下载不携带用户 API Key、翻译内容或其他业务数据。
- [ ] 自动更新失败不会破坏当前可运行版本，用户能看到可操作的错误与重试入口。
- [ ] 用户拒绝或暂不处理更新时，当前版本所有主功能继续可用，后续仍可从持续入口发起更新。
- [ ] macOS/Linux 不暴露未经验证的自动更新入口；后续接入必须补齐各自签名、公证、安装包与目标机验收。

## Out of Scope

- 强制更新、远端最低版本阻断，以及因未更新而禁用翻译等主功能。
- macOS/Linux 自动更新及其签名、公证和目标机验证。
- 自研更新协议、签名算法、安装器或更新服务。
- 应用内 Beta/Nightly 等预览通道及频道切换设置。
