# 实施 V1 核心 MVP

## Goal

以 `docs/lingostack-design.md` 的 V1（核心 MVP）为产品基线，在保留当前已经可用能力的前提下补齐缺口，使用户能够完成配置模型、文本翻译、变量命名、划词翻译、解释与朗读、收藏管理等核心链路，并使基础质量与开源门禁达到可发布状态。

## Background

- 来源需求：用户要求完成 `docs/lingostack-design.md` 中 V1（核心 MVP）的实施开发。
- 当前仓库已不是 V0 空壳：多个核心能力、前端视图、系统托盘、热键和测试已有实现；实施范围应依据现状差距确定，不能重复开发。
- 设计文档 §4.3、§7.3、§12 明确了较新的 V1 窗口决策：划词翻译由全局热键唤起主窗口翻译视图，不实现独立 PopClip 工具栏或独立翻译浮窗；§13 V1 清单中“自动弹 PopClip 式工具栏”视为尚未同步的旧表述。
- 文档翻译、自动弹工具栏优化与 Linux AT-SPI 完善属于 V1.5/V2，不纳入本任务。
- 既有规划已确认：变量命名提供 camelCase、snake_case、PascalCase、kebab-case、CONSTANT_CASE 五种形式，每次生成 5 个候选；收藏 V1 使用带时间/来源的扁平列表，分组/标签后移；Windows 默认热键、单实例强约束和跨平台配置目录方案沿用现状。
- 本次 V1 的功能运行验收限定在 Windows；macOS/Linux 必须保持编译通过，并对尚未实现的系统取词/TTS 返回明确的 `Unsupported`，不在本次补齐原生实现。

## Requirements

### R1. 核心 AI 链路

- 文本翻译与词条解释合并为一次 LLM 请求：响应同时包含译文和从原文/译文语境识别出的核心 IT 词条解释；变量名生成继续使用独立请求。两条链路均支持流式展示、重试和可理解的失败反馈。
- 每次翻译最多返回 5 个词条，只提取科技概念、编程/技术栈术语和产品名称等专业实体；普通单词不得作为词条。
- 每个词条必须实际出现在原文或译文中，按不区分大小写的词面去重，并标明 `technology`、`programming` 或 `product` 类别；应用只展示通过结构校验的前 5 项。
- 每个词条的解释使用原文语种，内容保持简洁，并结合本次原文与译文的具体语境，而不是给出脱离上下文的百科式释义。
- 支持 OpenAI 兼容协议、Anthropic、Gemini；Ollama 复用 OpenAI 兼容协议。
- 模型解析遵循“功能默认模型 → 全局默认模型 → 提示用户配置”的兜底顺序。
- 翻译目标语言遵循设计文档 §5 的语言映射规则。
- 翻译与命名 Prompt 支持用户覆盖，留空时使用受测试保护的内置模板；用户覆盖只改变内容风格，不能覆盖译文/词条机器协议。

### R2. 划词翻译与桌面集成

- 用户在其他应用选中文本后触发默认划词热键，应用唤起主窗口、切到翻译视图、读取选中文本并自动开始翻译。
- 取词失败时给出明确原因；辅助 API 不可用时按平台能力降级到剪贴板。
- 应用支持托盘驻留、单实例、打开主窗口和退出等基础行为。
- 全局热键支持配置、注册失败/冲突可见，并能引导用户修复。
- Windows 默认热键为：划词翻译 `Ctrl+Shift+D`、打开主窗口 `Alt+Space`；过时的“翻译浮窗”动作应从 V1 配置与界面中移除或兼容迁移。
- V1 不新增独立划词工具栏或独立翻译浮窗。

### R3. 结果操作与收藏

- 翻译结果支持复制、朗读和收藏；词条以译文下方的轻量标签呈现，鼠标悬停可查看解释。
- 词条标签的解释浮层必须同时支持键盘聚焦，避免只有鼠标用户能够访问；无专业词条时不显示空标签区域。
- 收藏支持持久化、搜索、JSON 导入/导出和朗读；V1 使用带收藏时间与来源的扁平列表，不包含分组/标签。
- 系统朗读必须有可见的开始/停止入口，并对不支持的平台或引擎失败给出明确反馈。

### R4. 设置与外观

- 设置页支持多提供商、模型列表、功能默认模型、全局默认模型、Prompt、语言映射、界面语言、热键和主题配置。
- 主题支持浅色、深色和跟随系统；界面至少支持中文与英文。
- API Key 只保存在本地，不进入日志、测试固件、Issue 模板或构建产物中的明文示例。

### R5. 质量与开源基建

- Rust 与前端的核心逻辑具有自动化测试；LLM 协议使用 mock 服务，不依赖真实密钥。
- CI 覆盖格式、lint、测试、构建、DCO、依赖审计和许可证通知产物检查。
- 仓库具备 MIT 许可证、贡献指南、Issue/PR 模板、Dependabot 配置和可生成的 `THIRD_PARTY_NOTICES`。
- 首个版本的自动打包发布、SHA256、Windows 签名、macOS 公证、release notes、双语 README 与完整治理 backlog 不作为本任务门禁。

## Acceptance Criteria

- [ ] AC1：在已配置可用模型的环境中，一次文本翻译请求可流式显示译文，并在响应完成且词条元数据校验通过后展示最多 5 个核心 IT 词条标签；成功后可复制、朗读、收藏，流式中断后保留已显示内容并可重试。词条协议损坏不得污染或隐藏译文。
- [ ] AC2：变量名生成一次模型请求得到 5 个中性候选，并分别展示 camelCase、snake_case、PascalCase、kebab-case、CONSTANT_CASE 五种形式；每项可一键复制。
- [ ] AC3：词条仅限科技概念、编程/技术栈术语和产品名称等专业实体，普通单词不进入标签；每个解释使用原文语种、结合当前语境且保持简洁，鼠标悬停或键盘聚焦均可查看。没有符合条件的词条时不显示空区域。
- [ ] AC4：Windows 上在任意应用选中文本后按默认划词热键，主窗口被唤起、进入翻译视图、填入原文并自动翻译；UIA 失败时剪贴板降级可观察。macOS/Linux 构建通过且未支持能力返回明确错误。
- [ ] AC5：用户可新增/编辑/删除 OpenAI 兼容、Anthropic、Gemini、Ollama 配置，并分别指定功能默认模型与全局兜底；缺失配置时得到可操作提示。
- [ ] AC6：语言映射、界面语言和浅色/深色/跟随系统主题在重启后保持，并按设计规则影响下一次翻译。
- [ ] AC7：收藏数据在重启后保持，搜索、JSON 导入/导出、复制和朗读均可用；无效导入不会破坏已有数据。
- [ ] AC8：热键冲突或系统注册失败会在设置页形成明确可见、可修复的状态；托盘菜单和单实例行为符合设计。
- [ ] AC9：`cargo fmt --all --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test --workspace`、`pnpm lint`、`pnpm build`、`pnpm test` 全部通过。
- [ ] AC10：CI 对受支持平台执行约定门禁，且 DCO、Dependabot、依赖审计、许可证通知生成和仓库贡献模板均有可复核配置。
- [ ] AC11：不实现文档翻译、独立划词工具栏、独立翻译浮窗、OCR、WebDAV 或 Linux AT-SPI 完善。

## Delivery Map

| Child task | Outcome | Order |
|---|---|---|
| `08-14-v1-translation-intelligence` | 单请求译文/词条协议、语言规则、LLM 可靠性、命名五候选边界 | 1 |
| `08-14-v1-settings-localization-hotkeys` | 真实设置、双语界面、主题单一真源、热键编辑与冲突恢复 | 2，依赖 1 的配置/语言契约 |
| `08-14-v1-desktop-result-actions` | 划词反馈、托盘路由、朗读停止与结果动作闭环 | 3，依赖 1–2 |
| `08-14-v1-quality-open-source` | 跨层测试、集成 `tauri-e2e-ci` 工作树产出的 Windows E2E/CI、桌面验收、许可证通知与全量门禁 | 4，依赖 1–3 及独立工作树产出完成评审 |

父任务不直接承载产品代码；负责源需求、跨子任务验收、设计文档同步与最终集成复核。

`tauri-e2e-ci` 独立工作树继续拥有 WebdriverIO Tauri 测试基础与 CI 基础文件；本分支前三个功能子任务不得重复搭建或修改同一套 E2E 基建。第 4 个子任务只在该工作树产出完成评审并进入本分支后补齐 V1 场景、许可证与最终门禁。

## Out of Scope

- 文档翻译及文档解析（V1.5）。
- 独立 PopClip 式工具栏、独立翻译浮窗与自动监听选区（V2 备选/V1.5 优化）。
- 扫描 PDF OCR、WebDAV、账号、云同步和内置模型额度。
- Linux AT-SPI 取词完善。
- 收藏分组/标签。
- 自动打包发布、SHA256、Windows 签名、macOS 公证、release notes、双语 README、labeler、用户指南/FAQ、ADR、截图/GIF 与完整社区治理 backlog。
- 独立的“解释”页面、模式切换或单独解释请求；V1 解释能力只随翻译结果返回。
