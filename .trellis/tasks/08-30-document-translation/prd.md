# 文档翻译：连续 Markdown 阅读器

## Goal

让用户导入 Markdown、文本型 PDF 或 DOCX 后，直接得到一篇可连续阅读的目标语言 Markdown 文档；应用只提供原文与译文两种阅读模式，翻译执行也不再按解析结构分块请求。

## Background

首版实现把持久化结构块直接映射为双栏阅读行。真实文档会产生数百个块，正文被大量分隔线、“原文/译文”标签和复制按钮打断，阅读连续性差；同时导入按钮、限制说明、任务操作和四种导出都堆在顶部，最小窗口下拥挤换行。

本轮用户明确要求：导入入口移到左侧文件列表底部；文档统一为 Markdown 结果；正文只在完整原文和完整译文之间切换查看。

## Requirements

### R1. 紧凑布局

- 顶部不展示长格式说明；“导入文档”按钮紧邻原文/译文切换右侧。
- 左侧只保留搜索、筛选和文档列表，不再用底部按钮容器占据可滚动空间。
- 主阅读区顶部左置原文/译文切换，并保留取消、重试/重新翻译、复制、导出、删除等当前文档操作；文件列表项视觉上只保留状态图标和文件名，不显示状态文字或百分比。暂停兼容状态不向用户承诺可继续。
- 在 864×576 最小窗口下，顶部操作不应因导入说明产生第二行拥挤布局。

### R2. 统一 Markdown 文档

- Markdown、文本型 PDF、DOCX 导入后都转换为规范化 Markdown 原文。
- 标题、段落、列表、引用、表格文字、代码块、行内代码、链接和图片说明尽可能保留为 Markdown 语义；不承诺 PDF/DOCX 视觉版式或分页。
- 扫描文档仍不做 OCR，直接返回“暂不支持”。50 MB、10 万可翻译字符和环境变量覆盖规则保持不变。
- 文档翻译 Prompt 要求输出目标语言 Markdown，并保持 Markdown 结构、代码和 URL。

### R3. 整篇翻译执行

- 解析块仅用于把源文件规范化为一篇 Markdown；每次文档翻译只发送这一整篇 Markdown，并在一次异步请求成功后原子保存完整译文。
- 前端 interface 不读取或呈现分片列表、分片复制、双栏对齐或文档术语列表。
- 列表不显示状态文字、百分比或“0/383 个结构块”这类实现计数；状态仅通过图标、可访问名称及当前记录操作表达。
- 翻译尚未成功时，译文阅读区只显示文档级翻译中状态；不得显示源片段、未翻译标记或任何内部执行结果。

### R4. 阅读、复制与导出

- 阅读区只提供“原文”和“译文”两个互斥模式，顺序为原文→译文。点击已完成记录时默认显示译文，点击其他状态记录时默认显示原文；导入成功并开始翻译后自动切到译文。手动切换在当前记录内保持，直到用户选择另一记录或导入新记录。
- 当前处于译文模式且文档正在翻译时，阅读区必须由持续加载层完整覆盖，直至翻译完成；加载期间不显示源文、局部译文或未翻译标记，完成后原位显示完整译文。
- Markdown 在应用内按标题、段落、列表、引用、表格、代码和链接渲染，不以纯文本 `<pre>` 展示。
- 复制操作复制当前模式的完整 Markdown 源文本。
- 导出操作把当前模式保存为 `.md`；没有完整译文时不导出伪造的局部结果，用户可改为导出原文。
- 首期不提供应用内编辑。

### R5. 生命周期与数据安全

- 导入后立即翻译；内容判重、取消、失败或取消后的整篇重试、后台运行、重启恢复、重新翻译原子替换和二次确认删除保持有效。内部暂停兼容状态仍可保留，但界面统一按已取消处理。
- 完全成功前，重新翻译不得覆盖旧的活动译文。
- SQLite 继续只保存内容哈希、显示文件名、源 Markdown 规范化数据、整篇译文、generation 与状态；旧术语/分块结果只为迁移兼容保留，不保存绝对路径或源文件二进制。
- 首期不显示文档自动术语；未来独立术语表能力继续由 GitHub Issue #20 承担。

### R6. 兼容与迁移

- 新数据库记录保存足以重建 Markdown 的块类型；旧记录迁移后按普通段落安全展示，不删库、不丢已有译文。
- Rust serde、Tauri IPC 与 TypeScript 联合类型必须用精确 JSON fixture 对齐。
- 前端不再需要的 `document_blocks` / `document_terms` reader IPC 应从生产 handler 和类型层移除，避免旧界面重新依赖内部结构。

### R7. 文档记录删除

- 已选文档的删除入口必须可用；确认对话框无法打开或后端删除失败时，界面要显示可观察错误，不得表现为点击无反应。
- 删除继续使用两次确认且不可撤销；任一步取消都不得删除记录。
- 删除成功后，SQLite 记录和左侧列表同步移除；若仍有其他记录，自动选中一个可继续阅读的记录。
- 文件列表右键菜单中的删除必须复用同一套确认和删除行为，不能形成第二套较弱的数据安全路径。

### R8. 桌面右键与阅读模式切换

- 应用全局禁用 WebView/浏览器默认右键菜单，避免暴露与桌面产品不一致的浏览器操作。
- 文档文件列表使用应用内右键菜单，可直接打开该记录的译文或原文，并通过同一套二次确认删除。
- 原文/译文阅读区使用应用内右键菜单，至少支持复制所选文字、复制当前完整 Markdown 和全选当前文档；首期仍不提供编辑。
- 原文/译文切换必须表现为一个互斥单选分段控件，当前模式有稳定高亮，并通过 radio 语义暴露 checked 状态；自动选择遵循“已完成记录→译文，其他记录→原文，新导入翻译→译文”。

### R9. 文档默认模型

- 设置 → AI 必须提供且只提供一个本地化为“文档” / “Document”的选择器，写入既有 `models.doc_translate` 配置。
- 未指定时明确提示“使用全局默认模型”，并沿用既有 feature → global default 解析规则，不新增平行配置或解析逻辑。
- 删除已分配的提供商时，文档翻译模型分配与其他功能分配一并清空。

### R10. 文档列表与设置/关于页视觉收尾

- 文档页顶部左侧显示原文/译文单选切换，不再显示当前文档的状态/进度 Label；任务状态只在文件列表项内表达。
- 左栏移除“文档记录”标题容器，搜索与筛选直接作为列表工具区；文件选择和拖放均支持一次导入多个文档，并为正在解析/翻译的列表项显示轻量动画图标。
- AI 设置中的文档模型行显示为简洁的“文档”业务 Label，仍写入同一个 `models.doc_translate` 字段并保留全局默认回退。
- 外观设置使用本地化的业务 Label 取代 `system` / `light` / `dark` / feature key 等内部值，并通过一致的纵向节奏避免标签、输入区和操作按钮紧贴。
- 关于页不再使用顶部标题和分割线；改为内容区居中的品牌 Logo、产品描述和一个更新检查占位按钮。

## Acceptance Criteria

- [ ] AC1：导入按钮位于顶部原文/译文切换右侧，左侧列表无底部按钮容器；864×576 下主工具栏保持紧凑可用。
- [ ] AC2：导入三种格式后，原文模式显示一篇连续、可渲染的规范化 Markdown。
- [ ] AC3：译文模式只在单次整篇请求成功后显示一篇完整的目标语言 Markdown，不显示局部正文、逐块卡片、双栏、块复制或术语面板。
- [ ] AC4：原文/译文切换、当前全文复制、当前 Markdown 导出均可用；点击已完成记录默认译文，其余记录默认原文，新导入翻译自动进入译文。
- [ ] AC5：文件列表项只显示图标与文件名，不显示状态文字、百分比或结构块数量；本地化状态仍可由辅助技术读取。
- [ ] AC6：标题、列表、引用、表格、代码、链接等 Markdown 语义在解析、翻译、显示和导出中保持可辨识；受保护内容不被改写。
- [ ] AC7：译文未完成时不导出伪造的部分 Markdown；完整译文不会带未翻译标记。
- [ ] AC8：取消/重试/重新翻译/删除、重复导入与后台持久化行为不回退；界面不宣称可从暂停位置继续。
- [ ] AC9：数据库迁移保留旧记录；新旧记录都能通过同一个连续 Markdown reader interface 读取。
- [ ] AC10：Rust、前端、生产隔离、feature-gated app、Windows Tauri E2E 和发行构建按影响范围通过；未手动或未跨平台执行的场景明确标注。
- [ ] AC11：删除按钮和文件右键删除都完成二次确认；成功后记录从持久化与列表消失，取消或失败不会静默。
- [ ] AC12：应用不再出现浏览器默认右键菜单；文件列表和 Markdown 阅读区显示应用内菜单，并提供各自约定的操作。
- [ ] AC13：原文/译文以单一 radio 分段控件呈现，当前项有明显高亮且辅助技术可读取 checked 状态。
- [ ] AC14：设置 → AI 可通过“文档” / “Document”选择模型并持久化 `models.doc_translate`；清空回退全局默认，删除该提供商会清空该分配。
- [ ] AC15：文档顶部左侧为高亮原文/译文切换且无进度 Label；左栏无“文档记录”标题，并可一次选择或拖放多个文件启动各自的后台翻译。
- [ ] AC16：解析中/翻译中的文件列表项有轻量动画，列表按钮可访问名称包含文件名与状态；可见 UI 不出现状态/百分比第二行，并遵守减少动态效果偏好。
- [ ] AC19：译文模式下的 translating 记录以覆盖整个 reader 的持续加载层呈现，父区为 busy；完成后加载层消失并显示完整译文，失败或取消不会卡在加载态。
- [ ] AC17：AI 设置文档模型行显示为“文档”；外观设置的主题与 Prompt Label 均为本地化业务文案，控件之间具有一致间距。
- [ ] AC18：关于页以居中品牌区呈现 Logo、描述和更新检查占位按钮，无顶部标题区域与分割线。

## Out of Scope

- OCR、PDF/DOCX 视觉版式复刻、分页保真。
- 逐块对照阅读、逐块复制、双语交替导出和四种导出矩阵。
- 应用内编辑、版本历史、跨文档术语管理。

## Technical Notes

- “整篇 Markdown”既是用户 interface，也是首期执行边界：一次异步请求只提交一篇规范化文档，成功后才原子显示完整译文。
- 用户本消息已明确要求设计并实施，本任务保持 `in_progress`，无需再次请求启动批准。
