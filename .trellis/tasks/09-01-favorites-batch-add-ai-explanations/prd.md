# 收藏批量新增与 AI 术语解释

## Goal

让用户能在“收藏”页面主动录入一个或多个术语或内容；保存后立即进入收藏列表，应用再以当前界面语言在后台生成面向程序员的术语解释。AI 延迟或失败不能阻塞、撤销或丢失已经保存的收藏。

## Background and Confirmed Facts

- 当前收藏使用 Zustand + IndexedDB，`Favorite` 持久化 `term/meaning/kind/source/createdAt`；批量写入已有单事务能力，但尚无解释任务状态或更新解释的业务动作。
- `lingostack-core` 已预留通用 `EXPLAIN_PROMPT`、`PromptOverrides.explain`、`Feature::Explain` 和 `ModelAssignment.explain`。本任务激活并扩展这套通用解释能力，不新增收藏专用 Prompt 或模型配置。
- 现有解释 Prompt 只描述单个术语的自然语言输出，尚无单条/批量统一的结构化响应协议；前端也尚未调用解释功能。
- 设置页当前未展示“解释”模型选择器和解释 Prompt 编辑器，流式 store 只覆盖翻译与命名。
- “跟随系统”的界面语言只能由 renderer 的 `resolveLocale` 解析为实际中文或 English；Rust 侧不能自行获得浏览器 locale。
- 在途任务 `09-01-translate-terms-favorites-layout` 已修改收藏长文本布局、规范化匹配和翻译术语解释语言。本任务必须基于这些改动增量实现，不得覆盖或回退它们。

## Requirements

### R1. 列表式批量新增

- 收藏页提供清晰的“新增”入口，打开符合现有 LingoStack overlay 视觉与无障碍契约的弹窗。
- 弹窗默认提供一个 item 输入行；用户可增加或删除 item，每个 item 独立编辑，不依赖换行或其他文本分隔符解析。
- 一次最多 10 个 item；达到上限后不能继续增加，并显示明确提示。
- 弹窗仅有一个批量保存主操作，提交前显示有效 item 数量；空 item 不得保存。
- 输入行、增加/删除操作、关闭和提交必须支持键盘访问、可见焦点、Escape 关闭、焦点恢复和本地化可访问名称。

### R2. 校验、去重与原子保存

- 提交前按现有收藏身份规则规范化内容：去除首尾空白、折叠连续空白、按大小写不敏感比较。
- 同一批次重复或已存在于已持久化收藏中的 item 不新增、不覆盖已有解释、也不触发 AI，并在对应输入行显示“重复”或“已收藏”。
- 所有非空、非重复 item 以来源“手动”、空解释和“等待生成”状态在一个 IndexedDB 事务中保存；任一写入失败时整批不落库，列表恢复原状，AI 不启动。
- IndexedDB 保存成功后，新收藏立即出现在列表中并关闭弹窗，不等待 AI 返回。

### R3. 通用解释 Prompt 与专用方法

- 扩展已有通用解释 Prompt，使同一 Prompt/方法同时支持 1–10 个 item，并输出可稳定映射回输入 item 的结构化 JSON。
- 不可覆盖的机器协议必须要求：只解释输入项、保持输入标识、每项至多一个解释、不得把 Markdown 或额外文本混入 JSON、技术名词/产品名/变量名/命令名保持原文。
- 用户自定义解释 Prompt 仍可控制解释风格，但不能删除批量 JSON 协议、界面语言约束或开发行业语言保护规则。
- 新增独立、类型化的后端解释方法；前端不得直接拼接通用 `chat_stream`。方法接收 1–10 个 item，后端也必须拒绝空数组、超过 10 项、空内容或重复输入标识。
- 解释方法使用 `Feature::Explain` 的模型分配并回退到全局默认模型；设置页展示“术语解释”模型选择器和解释 Prompt 编辑器。

### R4. 界面语言

- 每批请求在保存时解析并冻结实际界面语言；中文界面生成中文解释，English 界面生成英文解释。
- `system` 必须由前端解析后显式传入，后端不得将其猜测为原文语言、译文语言或固定默认语言。
- 请求进行中即使用户更改界面语言，本批结果仍使用提交时冻结的语种；后续新批次使用新设置。

### R5. 后台状态、部分成功与重试

- 解释生成在收藏持久化之后异步执行，任务状态必须位于 Zustand/持久化收藏数据中，不能只存在于弹窗或收藏视图组件的 `useState`。
- 一次新增最多对应一次批量 AI 请求，前端与后端上限一致为 10，不再拆分批次。
- 批量响应允许部分成功：有效结果立即更新对应收藏的解释；响应中缺失、重复、未知或无效的结果不得污染其他 item，缺失项标记失败。
- 请求级错误使本批仍未成功的 item 标记失败；已成功项不回滚。底层继续遵守“只在零输出时自动重试一次”的现有临时错误策略和共享 429 冷却。
- 失败项显示持续可见的失败状态和“重试”入口；重试只提交失败或上次未完成的 item。
- 应用重启后不得自动发起 AI 请求。加载到上次仍为“等待/生成中”的记录时，将其呈现为“上次生成未完成，可重试”，避免永久 busy 或无感费用。
- 用户删除正在生成的收藏后，迟到结果不得重建该记录或重新插入列表。

### R6. 持久化与兼容性

- 新增解释任务元数据采用向后兼容的可选字段，旧收藏无须迁移且保持原有展示语义；不得仅因增加对象字段而升级 IndexedDB object store 版本。
- 解释成功后继续把用户可见结果写入现有 `meaning`，因此搜索、朗读和既有列表展示自然复用。
- 导出 JSON 保持现有公开字段与格式，不导出内部等待/失败状态或错误详情；导入仍兼容旧 JSON，导入项不自动触发 AI。
- API Key、请求头和敏感配置不得进入收藏、错误状态、Prompt 输入、测试夹具或日志。

### R7. UI 与可访问性

- 收藏列表中的等待、成功、失败和重试状态与正在进行的长文本行布局兼容，不恢复嵌套卡片，不引入第二套颜色或组件库。
- 后台生成区域使用稳定的 `aria-live="polite"` / `aria-busy` 语义；失败原因和重试入口持续可见，避免同一错误被重复播报。
- 所有新增文案同时提供中文和 English；技术名词、模型名与用户输入保持原文。

## Acceptance Criteria

- [ ] AC1：收藏页可打开新增弹窗；默认一行，可增加/删除至最多 10 行，达到上限后增加动作禁用并显示提示。
- [ ] AC2：一次提交 1 个或 10 个有效 item 时，整批先原子写入 IndexedDB 并立即出现在收藏列表；AI 尚未返回时列表显示等待/生成状态。
- [ ] AC3：空行、同批重复和既有收藏重复均被准确定位；重复项不新增、不覆盖原解释、不进入 AI 请求。整批仅有重复/空项时不能提交。
- [ ] AC4：IndexedDB 批量保存中途失败时没有任何新收藏落库，列表恢复原状，解释 IPC 未被调用。
- [ ] AC5：单条与 10 条输入均通过同一个解释方法和通用解释 Prompt；后端拒绝 0 条、11 条、空内容和重复标识。
- [ ] AC6：中文界面和 English 界面分别生成对应语种的解释；`system` 使用 renderer 实际解析结果，运行中切换语言不改变已提交批次。
- [ ] AC7：Prompt 不变量测试覆盖内置/自定义 Prompt、开发术语保护、1 项/10 项 JSON 协议、语言约束和非法输出。
- [ ] AC8：批量响应中部分 item 成功、部分缺失/无效时，成功解释写入 `meaning`，失败项保持收藏并显示重试；重试请求只含失败项。
- [ ] AC9：应用加载到遗留“等待/生成中”记录时不自动调用 AI，而是显示“上次生成未完成，可重试”；删除生成中记录后，迟到结果不能使其复活。
- [ ] AC10：导入/导出 JSON 与历史收藏保持兼容，内部状态和错误不出现在导出文件，导入不会触发解释生成。
- [ ] AC11：设置页可分别选择“术语解释”模型并编辑/恢复通用解释 Prompt；未单独分配时使用全局默认模型。
- [ ] AC12：键盘可完成打开弹窗、逐项编辑、增加/删除、提交和关闭；dialog 语义、焦点恢复、忙碌与错误播报通过组件测试。
- [ ] AC13：相关 Rust/TypeScript 单元与组件测试、`pnpm lint`、`pnpm build`、`cargo fmt --all --check`、`cargo clippy --all-targets -- -D warnings`、`cargo test --workspace`、生产隔离和真实 Tauri E2E 均通过；自动化证据与人工视觉验收分别报告。

## Out of Scope

- 新增 LLM 提供商、协议或界面语言。
- 自动为历史收藏批量补解释，或因界面语言改变重写历史解释。
- 导入收藏后自动调用 AI。
- 允许用户通过重复新增覆盖或强制重生成已有收藏解释。
- 收藏分组、标签、排序重构或独立解释页面。
- 自动化系统级热键、外部应用取词或真实扬声器验收。
