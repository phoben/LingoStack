# Issue 23 技术设计

## 设计目标

以最小的共享契约修复三个独立但可统一验收的前端体验问题：AI 配置缺失应成为可操作状态、侧栏文字应按真实内容宽度切换、API Key 显隐只属于当前表单会话。

## 1. AI 可执行性与错误动作

### 1.1 共享纯逻辑

新增前端纯逻辑模块，按现有 Rust 规则解析某个 `Feature` 的模型：

1. 读取功能专用模型；
2. 不存在时回退到 `global_default`；
3. 校验 `provider_id` 对应的提供商仍存在；
4. 模型名为空也按配置缺失处理，避免发起必然无效的请求。

模块返回稳定的配置状态码，而不是面向用户的字符串。它不检查网络、不探测提供商服务，也不要求模型必须出现在提供商的展示列表中；这样既与 Rust `resolve_model` 的核心语义一致，也不会把远程模型发现（Issue #24）混入本任务。

### 1.2 翻译与命名

在构造消息前执行共享预检。配置缺失时抛出可识别的配置错误，由 `stream-store` 记录为 `configuration` 错误类型；普通 IPC/流式错误记录为 `request`。视图根据错误类型二选一：

- `configuration`：显示配置说明和“设置 AI”；
- `request`：保留当前错误文本和“重试”。

现有输出保留、流式状态和迟到回调序号守卫不变。

### 1.3 收藏词条解释与文档翻译

收藏解释和文档翻译已经持久化失败结果，不改变其数据模型或 Rust 执行流程。视图按“当前配置是否可执行”决定失败位置的动作：

- 当前配置缺失：以“设置 AI”替代“重试”；
- 当前配置可执行：保留“重试”。

文档工具栏中的重试/重新翻译入口也遵循同一判断。导入文档本身仍可完成；若自动翻译因配置缺失失败，既有失败快照继续保留，用户可从该记录直接进入 AI 设置。

### 1.4 设置深链

把设置子页状态提升到 `app-store`，新增显式的 `openSettings(section)` 动作。普通侧栏点击“设置”仍进入“通用”；“设置 AI”调用 `openSettings("ai")`。`SettingsView` 的子标签读取并更新 store，确保：

- 从任何业务视图可直接进入 AI；
- 已经位于设置页时也能立即切到 AI；
- 普通设置入口不被上一次深链状态污染。

新增共享的配置引导按钮组件，统一文案、图标、样式和导航行为。

## 2. 侧栏真实宽度判定

### 2.1 隐藏的固有宽度探针

`Sidebar` 保留一份不可见、不可交互且不进入无障碍树的导航尺寸探针。探针使用与真实导航一致的图标尺寸、字体、间距和内边距，并渲染当前语言的全部菜单文字。组件读取探针的固有宽度作为 `requiredWidth`。

以下事件会重新测量：

- 中文/英文界面语言变化；
- 字体加载完成；
- 探针尺寸被 `ResizeObserver` 检测到变化。

`showsSidebarLabels(availableWidth, requiredWidth)` 是唯一边界判定。显示态与隐藏态均使用同一比较，不引入不同的展开/收起阈值。

### 2.2 现有交互兼容

- 侧栏宽度继续由 `layout-store` 持久化。
- 拖拽与键盘只更新宽度；标签显示由同一纯函数派生。
- 双击根据当前真实显示态在最窄宽度与默认宽度间切换，避免固定阈值与实际显示态不一致。
- 无文字态继续通过按钮的可访问名称和 tooltip 暴露菜单含义。

## 3. API Key 显隐

`ProviderForm` 增加局部 `keyVisible` 状态，默认 `false`。输入框与眼睛按钮放在同一相对定位容器内：

- `false` 使用 `type="password"` 和“显示 API Key”；
- `true` 使用 `type="text"` 和“隐藏 API Key”；
- 按钮使用现有 ghost/icon 原语、Lucide `Eye` / `EyeOff`，并设置 `aria-pressed`。

`SettingsAi` 为每次新增/编辑会话提供稳定且不同的表单 `key`；保存或取消会卸载表单，因此重新打开必然恢复掩码。显隐状态不会进入 `ProviderConfig`。

## 4. 组件边界与本地化

- 按前端规范把 `SetSection` / `FuncCell` 从 `settings-view.tsx` 提取到共享组件，解除 `settings-ai.tsx` 与视图文件的循环依赖。
- 新增的“设置 AI”“AI 配置缺失”“显示/隐藏 API Key”等描述性文案全部进入中英文 i18n 字典。
- 错误区域继续使用 `role="alert"`；眼睛按钮和设置按钮具备明确可访问名称及可见焦点。
- 样式仅复用现有 Button/Input、语义 token 与 Lucide 图标，不新增颜色、圆角或视觉层级。

## 5. 兼容性、风险与回滚

- 不改 Rust、IPC、配置 JSON、IndexedDB schema 或依赖版本，无迁移要求。
- 最大风险是浏览器字体/布局测量的时序。以默认宽度作为初始安全值，并在字体与尺寸稳定后重测；测量失败时保持默认规则，避免文字闪烁或溢出。
- AI 预检必须覆盖功能专用、全局兜底、孤儿 provider 引用和空模型名，防止与 Rust 解析规则漂移。
- 回滚可按三个独立面拆分：共享 AI 引导、侧栏测量、API Key 显隐；均不影响持久化数据。

## 6. 验证策略

- 纯单测：AI 配置解析、侧栏宽度比较与双击目标。
- Store 测试：配置错误与普通请求错误分类；设置深链。
- 组件测试：四类功能的“设置 AI/重试”分流、直达 AI、中文/英文侧栏边界、API Key 默认/切换/重开。
- 全量前端门禁：`pnpm lint`、`pnpm test`、`pnpm build`。
- 不以 jsdom 的零尺寸布局冒充真实视觉验收；组件测试显式提供测量值，最终汇报自动化证据与未执行的真实桌面视觉验收边界。
