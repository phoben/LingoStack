# 修复翻译术语与收藏长文本布局

## Goal

让翻译结果中的术语解释遵循用户当前界面语言，并让术语收藏与收藏列表在长文本场景下保持直观、稳定、可访问，不再因悬浮说明或超长内容破坏主界面布局。

## Background and confirmed facts

- 当前界面语言只支持中文、English 与跟随系统；跟随系统最终解析为中文或 English（`src/lib/i18n.ts:385-392`、`src/components/views/settings-view.tsx:268-283`）。
- 当前强制术语协议要求 `explanation` 使用原文语言，而不是界面语言（`crates/lingostack-core/src/prompt.rs:38-45`）；Rust IPC 也只接收源语言与目标语言（`src-tauri/src/commands.rs:730-744`）。
- 当前术语说明位于译文滚动容器内部的绝对定位元素中（`src/components/views/translate-view.tsx:26-76,364-385`）。它虽不参与普通文档流，但会进入祖先滚动容器的 overflow/裁剪边界，因此不能保证真正浮在应用界面之上。
- 当前术语标签只有解释交互，没有收藏状态或收藏操作；现有收藏 store 已提供 IndexedDB 加载、新增、删除与失败回滚（`src/stores/favorites-store.ts`）。
- 当前收藏行是单行横向 flex；原文具有 `min-width:160px`，原文、释义都缺少可收缩宽度与长词换行约束（`src/components/views/favorites-view.tsx:185-237`）。截图中的长英文段落因此占据大部分横向宽度，把中文释义压成窄列并将元信息/操作推向右侧。
- 当前收藏数据允许长段落；翻译页现有收藏动作会保存完整“原文 → 译文”，并没有词条长度上限（`src/components/views/translate-view.tsx:272-284`）。因此长文本必须作为受支持数据处理，不能按脏数据丢弃。
- 当前已有术语键盘/悬停说明测试、收藏 store 回滚测试和收藏列表基本交互测试，但没有覆盖解释语言、浮层不影响滚动尺寸、术语收藏状态或长文本布局。

## Requirements

### R1. 术语解释语言

- 每次翻译生成的术语 `explanation` 必须使用本次请求生效的界面语言，而不是原文或译文语言。
- “跟随系统”必须使用前端已解析出的实际界面语言；当前产品范围为中文或 English。
- 该约束属于不可被用户自定义翻译 Prompt 删除的机器协议，并继续适用于所有 LLM 提供商。
- 不改变译文正文的源/目标语言选择与现有术语 JSON envelope 格式。

### R2. 术语说明浮层

- 鼠标悬停或键盘聚焦术语标签时显示说明；Escape、失焦和指针离开可关闭。
- 说明必须渲染在译文滚动容器之外的顶层 overlay 中，不增加译文容器的布局尺寸或滚动范围，也不被译文区域裁剪。
- 浮层在窗口边缘可自动夹取或翻转，最小窗口 `864×576` 下仍完整可读。
- 保留 `role="tooltip"`、`aria-describedby`、可见焦点环与 reduced-motion 兼容性。

### R3. 术语标签收藏

- 每个术语标签提供独立收藏图标；未收藏为空心，已收藏为实心并有不依赖颜色的可访问名称/状态。
- 进入翻译页或术语结果出现时，必须以 IndexedDB 中已持久化的收藏为事实来源恢复点亮状态，不能只依赖本次会话内存。
- 点击未收藏术语后，将“术语 → 当前解释”以来源“翻译”写入现有收藏能力；失败沿用现有回滚和错误 Toast。
- 按规范化后的“术语文本”判定是否已经收藏；下一次翻译给出不同解释时仍须点亮，避免同一术语因模型措辞变化被误判为未收藏。
- 点击已点亮图标直接取消对应收藏；若历史数据中存在同一规范化术语的重复条目，即使解释不同，一次取消也应全部清理，避免仍有同词记录却显示空心。
- 识别为已收藏时保留用户原先保存的解释，不因新翻译结果静默覆盖；点击取消时清理该规范化术语的全部历史重复项，避免仍有同词记录却显示空心。

### R4. 收藏长文本布局

- 收藏列表继续采用单层主面板、分割线行与轻量 hover，不恢复旧原型的嵌套卡片。
- 原文、释义必须位于有界且可收缩的内容列中；连续路径、命令、URL、中英混排和换行文本均不能撑开列宽或挤压元信息/操作区。
- 元信息与朗读/删除操作保持可见、可点击，不因内容长度漂移到视口外。
- 最小窗口 `864×576` 与常用窗口宽度下不得出现意外水平溢出；列表自身保持纵向滚动。
- 原文和释义默认各最多显示 3 行；仅当内容实际溢出时提供明确的展开入口，展开当前行后显示全文，并可再次收起。
- 展开状态只属于当前界面会话，不写入 IndexedDB，也不改变导入/导出数据。

### R5. 兼容性和边界

- 不迁移 IndexedDB schema，不修改导入/导出 JSON 格式，不丢弃既有收藏。
- 不新增颜色体系或第二套 UI 原语；继续使用现有 Tailwind 语义 token、Lucide 图标和手写 Button。
- 不改动翻译正文协议、收藏搜索/筛选、TTS、导入导出与删除业务语义，除非实施中发现是满足上述要求的必要条件并重新评审。

## Acceptance Criteria

- [ ] AC1：界面为中文时，无论原文是 English/中文/日本語，术语解释请求约束均明确为中文；界面为 English 时均明确为 English。Rust 单测覆盖内置 Prompt 与自定义 Prompt 两条路径。
- [ ] AC2：术语 envelope 结构与解析结果保持兼容，现有流式解析测试全部通过。
- [ ] AC3：打开术语说明前后，译文滚动容器的 `scrollWidth` / `scrollHeight` 不因浮层增加；浮层挂载在顶层 portal，窗口边缘定位测试通过。
- [ ] AC4：鼠标、Tab/Shift+Tab、Escape 均可完成术语说明交互，`role="tooltip"` 与 `aria-describedby` 状态正确。
- [ ] AC5：已持久化的同一术语即使在后续翻译中得到不同解释，也显示实心收藏图标；未收藏显示空心图标。空心点击新增，实心点击取消；同一规范化术语的历史重复项一次取消后全部移除。原收藏解释不被新结果静默覆盖；新增、取消与失败回滚均有组件/store 测试。
- [ ] AC6：用截图同量级的长英文原文、中文释义、长路径和连续无空格 token 渲染收藏行，在 `864×576` 与默认窗口下不出现横向溢出，元信息及两个操作按钮保持可见；默认各最多 3 行，展开后全文可见，收起后恢复 3 行。
- [ ] AC7：收藏搜索、筛选、朗读、删除、导入导出与空态现有测试继续通过；新增长文本 DOM/CSS 约束测试与桌面实窗人工验收。
- [ ] AC8：`pnpm lint`、`pnpm build`、相关 Vitest、Rust Prompt 单测以及 `git diff --check` 均通过；真实桌面验收与静态/自动化门禁分开报告。

## Out of Scope

- 新增界面语言或翻译语言。
- 重做收藏数据模型、分组/标签系统或 IndexedDB 版本迁移。
- 重构所有页面的 Tooltip/Popover；除非调研证明已有多个调用点需要同一原语，本任务优先解决术语说明场景。
- 改造整段翻译的现有收藏按钮与历史重复收藏数据。
