# 翻译与命名功能体验优化（issue #2）

来源：https://github.com/phoben/LingoStack/issues/2 （enhancement，2026-08-06 提出）

## Goal

主窗口跑通之后的第一轮体验打磨。命名页从「选一种规范、生成一批」改成
「一次给全五种规范、平铺对照」；翻译页把常用动作放到手边、去掉多余装饰；
并修掉一个真实缺陷——翻译还在生成时切走页面再回来，结果就没了。

用户价值：命名少点几次、结果能横向比；翻译页操作不再只在一侧；
切页面去查收藏、改设置回来，正在跑的活儿还在。

## Background：现状事实（已核查）

命名页 `src/components/views/naming-view.tsx`
- 顶部一行里塞了三样东西：描述输入框、五个规范切换按钮、生成按钮（右推）。
- 一次只按当前选中的一种规范生成，切规范不自动重算，要再点一次生成。
- 候选纵向单列排列；底部一行小字标注本次用的模型。
- 内置命名指令要求「3–5 个候选、每行一个」：`crates/lingostack-core/src/prompts/naming.txt:4`。
- 五种规范的清单与展示名在 Rust 与前端各有一份镜像：
  `crates/lingostack-core/src/naming.rs:20`、`src/lib/config-types.ts:103`。
- 配置里存着「启用哪几种规范」，默认五种全开，但设置页没有编辑入口，
  命名页也没读它，是硬编码的五种：`src/lib/config-types.ts:84`。

翻译页 `src/components/views/translate-view.tsx`
- 原文面板顶栏右侧显示字符数（`:215`），面板没有底栏，也没有任何动作按钮。
- 译文面板顶栏右侧显示模型名（`:232`），底栏三个图标按钮（朗读/收藏/复制）靠右（`:259`）。
- 生成中在译文末尾画一个闪烁竖条（`:241`）；命名页也有一个同款闪烁块（`naming-view.tsx:166`）。
- 顶部工具条已有状态标记（待翻译 / 流式 / 已完成 / 错误），能替代闪烁光标表达「在跑」。

模型信息的当前露出位置
- 标题栏 `src/components/title-bar.tsx` 右侧只有主题切换 + 三个窗口按钮，没有模型入口。
- 界面里没有状态栏；模型名只在翻译页译文面板顶栏与命名页底部各露一次。
- 设置页是模型指定的唯一编辑入口（`src/components/settings-ai.tsx:15`
  按功能配翻译 / 命名 / 解释 / 全局默认）。

「切页面丢结果」的根因
- 六个视图是按当前选中项条件渲染的：`src/App.tsx:60`。切页面等于把上一个视图整个拆掉，
  它记在自己身上的原文、译文、进度全部归零。
- 后端那边活儿并没停：`chat_stream` 是独立的异步任务（`src-tauri/src/commands.rs:76`），
  仍在往前端推增量，只是接收方已经不存在了。
- 所以这是纯前端的「结果没地方存」问题，后端与协议层不用动。

## Requirements

R1 命名页一次产出五种规范的全部结果，用户不再需要先选规范。
   **五列是同一批词的五种写法**（已决策）：一次生成只发一次模型请求，取回 5 个候选词，
   五种写法在本地铺开。因此五列严格逐行对齐——第一行就是同一个词的五种形态，
   用户先横向挑词、再按当前语言取对应那一列。
   连带影响：内置命名指令不再按单一规范出词，改为出中性候选词；
   `crates/lingostack-core/src/prompts/naming.txt` 与守它的断言
   `crates/lingostack-core/src/prompt.rs:105` 需同步调整。
   设置页当前没有 Prompt 编辑入口（已核查），此改动不影响任何已有用户设置。
R2 命名页输入区精简：去掉描述性标签，输入框与生成按钮居中；规范切换条随 R1 一并撤掉。
R3 命名结果按五列平铺，每列一种规范、五行候选；每列一张独立卡片，
   卡内用分割线隔开各行，列与列之间留间距。每行仍可一键复制。
R4 原文面板补上朗读、收藏、复制三个动作，放在原先显示字符数的位置；字符数不再显示。
R5 模型信息整体撤出功能页面：译文面板顶栏与命名页底部的模型标注都去掉；
   译文面板底栏三个图标按钮改为左对齐。
   **配套决策（用户 2026-08-07）**：issue 原提的「标题栏模型入口 + 临时切换」撤销，
   模型指定统一留在设置页。效果是模型信息只有设置页一个入口，不再散落。
R6 生成过程中不再出现闪烁光标；进度由既有状态标记表达（命名页同款闪烁块一并去掉）。
R7 切换页面不中断、不丢弃任何页面正在进行的生成任务；切回来能看到期间累积的全部内容
   与当前状态（包括跑完了、或中途出错可重试）。技术方向见 design.md §1.1：
   任务态从视图组件上移到共享状态层，视图可自由卸载而不影响进行中的任务。

## Acceptance Criteria

- [ ] AC1（R1/R2）命名页顶部只有居中的描述输入框与生成按钮，没有规范切换条、没有描述标签。
- [ ] AC2（R1/R3）点一次生成，五列卡片同时出结果；每列表头是该规范名，列内五行候选，行间有分割线。
- [ ] AC3（R3）任一行的复制按钮点下后复制该候选，并给出「已复制」反馈。
- [ ] AC4（R4）原文面板顶栏右侧是朗读/收藏/复制三个按钮，不再显示字符数；
      朗读读的是原文，复制复制的是原文。
- [ ] AC5（R5）翻译页与命名页均不出现模型名；译文面板底栏三个按钮靠左；标题栏无模型入口。
- [ ] AC6（R6）翻译与命名生成过程中，页面上不出现闪烁光标；状态标记正确反映进行中/完成/错误。
- [ ] AC7（R7）发起翻译后立即切到收藏页停留数秒再切回翻译页：译文包含期间产生的全部内容，
      原文框内容仍在，状态与不切页时一致；命名页同样满足。
- [ ] AC8 门禁全绿：`pnpm lint`、`pnpm test`、`pnpm build`、`cargo fmt --all --check`、
      `cargo clippy --all-targets -- -D warnings`、`cargo test --workspace`。
- [ ] AC9 新增行为带测试：候选词到五种写法的转换、五列分组、跨页面任务状态保持。

## Out of Scope

- 文档页仍是静态示例，不接真实解析与翻译（P1 / V1.5）。
- 设置页不新增「启用哪几种命名规范」的编辑入口。
- 不改后端流式协议、不改四种提供商适配、不改内置翻译指令。
- 不做取消 / 中止正在进行的生成。
- 不引入状态栏。
- 不做标题栏模型切换入口（issue 原列诉求，已撤销，见 R5）。
