# 本地一键发布构建脚本

## Goal

让 Windows 开发者通过一个交互式 PowerShell 入口同步升级 LingoStack 版本，并选择生成免安装程序或 NSIS 安装程序；全过程能够看见关键阶段、构建结果、日志与产物绝对路径。

## User scenarios

1. 开发者运行脚本，看到当前统一版本，选择“免安装版”或“安装版”，输入新版本后完成构建。
2. 开发者在自动化或回归测试中通过参数跳过交互，得到与交互模式相同的版本同步和退出码。
3. 版本来源不一致、版本格式错误、依赖缺失或构建失败时，脚本明确失败阶段，不输出伪成功结果。

## Requirements

- R1. 主入口为仓库内 PowerShell 7 脚本，可从任意当前目录启动，并自动解析仓库根目录。
- R2. 未传参数时询问构建类型和新版本；菜单包含“免安装版”和“安装版”，版本提示显示当前版本。
- R3. 当前版本必须从 `package.json`、根 `Cargo.toml` 的 `[workspace.package]`、`src-tauri/tauri.conf.json` 三处读取并校验一致；不一致时失败关闭。
- R4. 新版本必须是合法 SemVer，并同步写入上述三处；允许输入当前版本以便仅重新构建。
- R5. 免安装版执行 Tauri release build 的 `--no-bundle`；安装版只生成 Windows NSIS 安装程序。
- R6. 控制台输出阶段、版本、构建类型、实际命令、耗时、退出码和最终产物绝对路径；完整原生命令输出同时写入 `target/release/logs/`。
- R7. 任一外部命令失败时脚本返回非零退出码并给出日志路径；不得吞错或把旧产物报告为本次成功产物。
- R8. 版本文件写入阶段发生异常时恢复三份原内容；进入构建后若构建失败，保留新版本以便修复后重试。
- R9. 提供非交互参数和无真实构建测试入口，用于确定性验证版本同步、输入校验与命令选择，不调用真实发布网络或密钥。
- R10. 不自动提交、推送、签名或发布产物。

## Acceptance Criteria

- [ ] AC1. 无参数运行时可完成两次交互，并在版本提示中看到当前版本。
- [ ] AC2. 选择免安装版后实际命令包含 `pnpm tauri build --no-bundle`，成功时只报告本次生成的 `target/release/lingostack-app.exe`。
- [ ] AC3. 选择安装版后实际命令包含 `pnpm tauri build --bundles nsis`，成功时报告本次生成的 NSIS `.exe`。
- [ ] AC4. 合法版本同步写入三处版本源；三处初始值不一致或版本不合法时不改文件并返回非零。
- [ ] AC5. 版本同步写入异常不会留下部分升级状态。
- [ ] AC6. 构建输出实时显示并落盘；最终摘要包含成功/失败、耗时、退出码、日志和产物绝对路径。
- [ ] AC7. 构建失败不会把构建前已存在的产物当成新结果，且脚本进程返回外部构建失败码。
- [ ] AC8. 自动化测试覆盖两类命令选择、版本同步、版本不一致、非法版本和失败退出边界。

## Out of scope

- macOS/Linux 打包、代码签名、公证、自动上传 Release、Git 提交或 changelog 生成。
- 安装版 MSI；本任务固定使用更适合本地分发的 NSIS `.exe`。
